# Игровая больница и агент «Доктор Пульс»

## Назначение

«Доктор Пульс» — детский агент для ролевой игры в больницу. Это не медицинский
консультант. Все пациенты, показатели и процедуры вымышлены, а состояние
определяет только проверенный каталог Gateway — не LLM.

Режим доступен в Android и веб-интерфейсе. Обычный голосовой и текстовый чат с
агентом остаётся доступен рядом с игровой карточкой.

## Как выглядит игра

1. Ребёнок открывает Доктора Пульса и нажимает большую кнопку больницы.
2. Выбирает вымышленного пациента по картинке и короткому названию.
3. Видит декоративную кардиолинию, пульс, давление, температуру и настроение.
4. Отмечает только предложенные сценарием действия крупными кнопками.
5. Gateway идемпотентно сохраняет отметку и меняет игровые показатели.
6. Ответ сохраняется в обычной истории и озвучивается выбранным голосом агента.

Тихий звук монитора отключается отдельной кнопкой. Пауза сохраняет карточку,
продолжение возвращает её в активное состояние, а выход закрывает игровой режим.

## Неподвижная граница безопасности

- диагноз, лекарство, дозировка и схема лечения не генерируются;
- укол и капельница являются только отметками уже выполненной вымышленным
  старшим врачом процедуры — техника выполнения не объясняется;
- реальные медицинские приборы и данные к игре не подключаются;
- фото травм и медицинская диагностика по изображению не используются;
- фраза от первого лица о боли, крови, затруднённом дыхании, плохом
  самочувствии, проглоченном лекарстве или травме немедленно ставит игру на
  паузу и просит позвать взрослого;
- игровые сведения не попадают в долгосрочную память автоматически.

Защита состоит из трёх независимых слоёв: фиксированной модели переходов,
`SafetyPolicyEngine` до/после LLM и обязательного prompt-контекста активной
карточки.

## API

```text
GET  /v1/clinic/cases
GET  /v1/clinic/conversations/{conversation_id}
POST /v1/clinic/conversations/{conversation_id}/cases/{case_id}/start
POST /v1/clinic/conversations/{conversation_id}/actions/{action_id}
POST /v1/clinic/conversations/{conversation_id}/pause
POST /v1/clinic/conversations/{conversation_id}/resume
POST /v1/clinic/conversations/{conversation_id}/leave
```

Admin API под браузерной сессией:

```text
GET    /api/clinic/catalog
GET    /api/clinic/sessions
POST   /api/clinic/sessions/{session_id}/pause
POST   /api/clinic/sessions/{session_id}/resume
DELETE /api/clinic/sessions/{session_id}
```

Сброс удаляет только игровое состояние; сообщения остаются под общим сроком
хранения истории. Короткоживущие карточки и события удаляются общим retention.

## Конфигурация и выпуск

Каталог находится в `gateway/app/clinic/catalog.json`, валидируется Pydantic и
имеет `schema_version`. Произвольное редактирование переходов из админки
намеренно отсутствует: изменение проходит Git, тесты и воспроизводимый release.

Release passport показывает версию и SHA-256 каталога, поэтому расхождение
запущенного Gateway с ожидаемым содержимым видно без просмотра текста сценариев.
Внутренний endpoint `/internal/clinic-metrics` содержит только агрегаты
`operation.success/error`, без реплик, ID диалогов и сведений о пациенте.

Схема БД создаётся миграцией `020_add_clinic_game`. Стандартное восстановление
на чистых VM применяет её через `alembic upgrade head`; отдельных ручных SQL или
невосстанавливаемых игровых файлов нет.

Архитектурное решение: [ADR 045](adr/045-deterministic-clinic-play.md).
