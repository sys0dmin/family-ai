# Родительская обратная связь и подтверждённые regression cases

## Статус

Accepted

## Контекст

История сообщений хранится десять дней и доступна родителю в защищённой
админке. Сейчас родитель может увидеть плохой ответ, но не может указать тип
проблемы, проследить повторяемость и воспроизвести случай после изменения
prompt или Safety Policy.

Автоматически превращать детские сообщения в постоянный тестовый набор нельзя:
это нарушило бы ожидаемый retention и создало скрытое бессрочное хранилище
разговоров Леры. Одновременно feedback, отделённый от исходного сообщения,
теряет контекст и может пережить удаление истории случайно.

## Решение

Добавить два разных агрегата с разным жизненным циклом.

`MessageFeedback`:

- принадлежит одному `Message` и содержит стабильную причину и необязательную
  заметку родителя;
- не копирует текст сообщения;
- имеет не более одной активной оценки на сообщение;
- удаляется каскадно вместе с сообщением и обычным 10-дневным retention;
- используется только для защищённого списка и агрегированной статистики.

`RegressionCase`:

- создаётся только отдельным подтверждающим действием родителя;
- перед сохранением показывает полный prompt, ожидаемый ответ, агента и
  ожидаемые safety/technical результаты в редактируемой форме;
- хранит самостоятельную копию только подтверждённого текста;
- может ссылаться на исходный feedback, но при его удалении получает `NULL` и
  сохраняется до явного удаления родителем;
- запускается через тот же `StudioService`, provider interfaces и Safety Policy,
  что и ручная тест-студия, без записи в историю диалогов.

Стабильные причины feedback: фактическая ошибка, вопрос не понят, слишком
сложно, ложная блокировка, нарушен характер агента, плохой голос, плохой Vision
и другая проблема.

Результат запуска case не хранится автоматически. API возвращает фактический
финальный ответ, safety action, rule id и нормализованную техническую ошибку, а
также отдельные результаты сравнения. Это избегает накопления model outputs и
позволяет повторять один case после каждого изменения.

Экспорт содержит только явно подтверждённые regression cases. Feedback и
исходная история в экспорт не входят.

## Альтернативы

- Добавить поля оценки прямо в `messages`: отклонено, потому что смешивает
  разговор и родительский workflow и затрудняет расширение причин.
- Автоматически копировать все отмеченные сообщения в regression suite:
  отклонено из-за privacy и отсутствия явного подтверждения полного текста.
- Хранить только хеши сообщений: недостаточно для воспроизводимого prompt test.
- Сохранять каждый фактический результат запуска: отложено; для домашнего
  проекта достаточно немедленного сравнения без нового retention-контура.
- Проверять cases отдельным упрощённым safety-кодом: отклонено из-за риска
  расхождения с production pipeline.

## Последствия

Положительные:

- родитель видит повторяющиеся классы проблем;
- история сохраняет прежний retention;
- постоянный тестовый текст появляется только после осознанного подтверждения;
- prompt и safety-регрессии проверяются через production-like pipeline;
- удаление и экспорт имеют однозначные границы.

Отрицательные:

- появляются две таблицы, миграция и дополнительный Admin UI;
- ожидаемый ответ и safety-результат требуют ручного решения родителя;
- model output может быть недетерминированным, поэтому сравнение ответа
  нормализованное и информативное, а не блокирующий exact snapshot по умолчанию.
