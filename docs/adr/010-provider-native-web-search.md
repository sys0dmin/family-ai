# Provider-native веб-поиск как разрешаемый инструмент

## Status

Accepted

## Context

Языковая модель не является каталогом песен и выдумывает правдоподобные названия при поиске по текстовому фрагменту. Текущий Groq GPT-OSS provider поддерживает встроенный `browser_search`, который можно вызвать в том же Chat Completions запросе. Инструмент может иметь отдельную стоимость и передаёт поисковый запрос внешнему сервису.

## Decision

Добавить в нормализованный `ChatRequest` независимую возможность `ProviderTool.WEB_SEARCH`. Конкретный adapter сам решает, как отобразить её в API поставщика. Для Groq OpenAI-compatible adapter используется `{"type": "browser_search"}`. Отображение включается только runtime-настройкой `web_search_tool_type`.

Вызов возможен только у агента с явным инструментом `web_search`. Первым таким агентом является «Нотка». Остальные персонажи не получают эту возможность автоматически. Поисковые URL и технические цитаты не выводятся в детский интерфейс.

## Alternatives

- Довериться памяти LLM: отклонено из-за подтверждённых галлюцинаций.
- Зашить Groq tool в ConversationService: отклонено, чтобы бизнес-логика не знала о формате одного provider.
- Включить поиск всем агентам: отклонено из-за приватности, стоимости и непредсказуемой задержки.

## Consequences

Положительные: поиск по тексту песни получает внешнее подтверждение; provider можно заменить; capability выдаётся по принципу least privilege.

Отрицательные: текст поискового запроса передаётся внешнему search provider через Groq; ход может стать дороже и медленнее; качество зависит от индекса веб-поиска.
