# Визуальные baseline для Admin UI и Android

## Статус

Принято

## Контекст

Обычные unit и widget-тесты подтверждали наличие элементов и отсутствие
исключений, но не обнаруживали смещение кнопок, наложение блоков и Flutter
overflow. Такие дефекты несколько раз находились только после ручного открытия
Admin UI или Android-приложения.

Production-скриншоты нельзя использовать как эталоны: они содержат изменяемые
данные и могут раскрыть историю, настройки или технические идентификаторы.

## Решение

Хранить в Git осознанно подтверждённые PNG baseline для критических desktop,
mobile, portrait, landscape и keyboard-состояний.

Admin UI снимается установленным headless Chrome или Edge из настоящих HTML и
CSS. Отдельный fixture подставляет только стабильные синтетические данные и не
входит в production JavaScript. Стандартный Python-компаратор декодирует RGB/RGBA
PNG без новой зависимости и допускает малое различие anti-aliasing. Перед
сравнением DOM отдельно проверяется на горизонтальный overflow.

Android использует штатный механизм `matchesGoldenFile` из `flutter_test`,
настоящие widgets и assets, mock Gateway и in-memory аппаратные адаптеры.
Стабильный тестовый Roboto загружается из активного Flutter SDK. Android release
builder обязан выполнить goldens из точного собираемого commit.

Изменение baseline разрешено только отдельным флагом и требует ручного просмотра
всех изменённых PNG.

## Альтернативы

### Playwright и отдельный JavaScript toolchain

Отклонено: ради пяти локальных Admin-снимков пришлось бы добавить Node,
browser-download и новый lockfile.

### Selenium или Python image library

Отклонено: это добавляет зависимости, хотя установленный Chromium и стандартная
библиотека покрывают текущий контур.

### Только проверки размеров DOM без PNG

Отклонено: они не обнаруживают визуальное исчезновение, неверные отступы, цвета
и большую часть перекрытий.

### Production-данные как fixture

Отклонено по требованиям приватности, воспроизводимости и безопасности ребёнка.

## Последствия

Положительные:

- layout-регрессии обнаруживаются до публикации;
- тестовые данные стабильны и не связаны с Лерой;
- Android keyboard и landscape становятся явным контрактом;
- не добавляется runtime-зависимость или UI-фреймворк.

Отрицательные:

- подтверждённые PNG увеличивают размер репозитория;
- обновление Chrome или Flutter может потребовать осознанного обновления
  baseline;
- Admin suite поддерживается на Windows-станции с Chrome или Edge;
- agent chooser baseline проверяет сетку и подписи, а детальный character asset
  отдельно покрывается chat goldens из-за ограничений WebP preloading в
  `flutter_test`.
