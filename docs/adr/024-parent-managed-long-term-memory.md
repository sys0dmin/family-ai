# Родительская долгосрочная память как изолированный домен Gateway

## Статус

Принято

## Контекст

История сообщений удаляется через десять дней и не подходит для устойчивых
интересов, предпочтений и учебного прогресса Леры. Автоматическое извлечение
фактов языковой моделью создало бы риск закрепить догадку, ошибку распознавания
речи или случайную реплику как правду.

Отдельный Memory Service предусмотрен будущей архитектурой, но сейчас проект
работает на двух application-хостах, имеет один детский профиль и не нуждается
в дополнительном процессе, сетевой аутентификации и новой точке отказа.

## Решение

Создать изолированный домен `gateway.app.memory`:

- `MemoryRepository` является стабильным persistence-портом;
- `SqlAlchemyMemoryRepository` хранит записи в PostgreSQL;
- `MemoryService` управляет подтверждёнными записями и строит ограниченный
  provider-neutral контекст;
- Conversation Service зависит от `MemoryService`, а не от таблицы или
  конкретного LLM provider;
- HTTP CRUD доступен только через существующую защищённую Admin UI;
- детский API, LLM tools и provider API не имеют операции создания памяти.

Запись содержит категорию, тему, краткое подтверждённое сведение, тип и дату
источника, необязательную родительскую заметку, автора и timestamps
подтверждения. Разрешены только категории `interest`, `preference` и
`learning_progress`.

В модель передаются максимум 30 последних подтверждённых записей. Родительская
заметка об источнике не передаётся. Контекст маркируется как данные, а не
инструкции, и запрещает давление интересами, удержание внимания, слежку и
подмену родителей.

Редактирование повторно подтверждает запись. Удаление физическое и начинает
действовать для следующего LLM-запроса. Очистка краткосрочной истории не
затрагивает долгосрочную память.

## Альтернативы

### Автоматически извлекать факты из каждого диалога

Отклонено: модель могла бы превратить предположение или ошибку STT в постоянный
факт без ведома родителя.

### Сразу развернуть отдельный Memory Service

Отложено: логическая граница уже существует, а новый процесс пока не даёт
продуктовой пользы, сопоставимой с эксплуатационной сложностью.

### Использовать сообщения или векторную базу

Отклонено: сообщения имеют ограниченный срок хранения, а семантический поиск не
обеспечивает родителю простой контроль над каждым фактом.

## Последствия

Положительные:

- только родитель определяет долговременные сведения;
- записи прозрачны, исправимы и удаляемы по одной;
- память не зависит от LLM provider и переживает очистку истории;
- домен можно вынести за REST API будущего Memory Service.

Отрицательные:

- родитель заполняет записи вручную;
- память пока использует БД и lifecycle Gateway;
- при большом числе профилей потребуется отдельная политика выбора и
  релевантности записей.
