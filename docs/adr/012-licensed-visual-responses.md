# Лицензированные визуальные ответы

## Status

Accepted

## Context

Лера пока не читает, поэтому фотография часто объясняет устройство, животное или природное явление лучше длинного текста. Изображения должны быть безопасными для ребёнка, сопровождаться атрибуцией, работать в текстовом и голосовом режимах и не связывать Gateway с конкретным поставщиком.

## Decision

Добавить заменяемый `ImageSearchProvider` и capability агента `image_search`. Первым провайдером использовать Openverse: только HTTPS, `mature=false`, пустой список sensitivity и результаты с лицензией. Gateway формирует короткий тематический запрос без имени ребёнка и семейных деталей, сохраняет метадату в отдельной таблице `message_media` и проксирует бинарное изображение детскому браузеру.

Одно сообщение получает не более одного изображения. Capability включена для «Учителя-друга», «Почемучки», «Мурки» и «Байтика». Фотографии Мурки носят только образовательный характер и не подтверждают вид, съедобность или безопасность. Генерация сказочных иллюстраций остаётся отдельной будущей capability.

## Alternatives

- Возвращать URL, придуманный языковой моделью: нет гарантии существования, лицензии и безопасности.
- Загружать внешнюю картинку прямо в браузере: раскрывает внешний запрос и IP клиента, усложняет контроль типа содержимого.
- Генерировать каждую картинку: дороже и хуже подходит для показа реального оборудования и природы.
- Хранить бинарные файлы в PostgreSQL или Ceph: для домашнего MVP создаёт лишний объём и жизненный цикл кэша.

## Consequences

Провайдера можно заменить без изменения диалоговой логики и API сообщения. Атрибуция и десятидневный срок хранения истории распространяются на медиа автоматически через внешний ключ с каскадным удалением. Ответ немного замедляется при визуальном поиске, внешний источник может временно не ответить, а его классификация чувствительного контента не является абсолютной гарантией; в этом случае Gateway возвращает обычный текст без картинки.
