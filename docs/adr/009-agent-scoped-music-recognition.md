# Распознавание мелодий как инструмент агента

## Status

Accepted

## Context

STT распознаёт речь, но не даёт языковой модели надёжно услышать мелодию. Для игры «угадай песню по напеву» нужен отдельный audio-fingerprint/cover-song provider. Вызов такого сервиса передаёт запись внешней стороне, поэтому он не должен включаться для всех диалогов.

## Decision

Ввести независимый `MusicRecognitionProvider` с нормализованными моделями запроса и кандидатов. Первый адаптер — ACRCloud. Выбор провайдера и секреты хранятся в runtime-конфигурации.

Вызов разрешён только когда у закреплённого за диалогом агента есть `music_recognition`. Результат добавляется как временный system context и не сохраняется в истории. Метаданные provider считаются недоверенными. При ошибке или отсутствии совпадений агент не выдумывает песню.

Исходное аудио не сохраняется Family AI и удаляется из памяти после хода.

Текстовая догадка LLM не считается результатом инструмента. Агент не должен перечислять правдоподобные варианты: без уверенного совпадения он запрашивает ещё один фрагмент. Gateway явно маркирует повторные ходы как продолжение текущего диалога, чтобы персонаж не здоровался и не представлялся заново.

## Alternatives

- Попросить LLM угадывать по STT: отклонено, потому что напев без слов теряется.
- Зашить ACRCloud в VoiceService: отклонено, так как это связало бы бизнес-логику с одним поставщиком.
- Отправлять все голосовые ходы на распознавание: отклонено из-за лишней передачи детского аудио.

## Consequences

Положительные: замена поставщика не затронет VoiceService или агента; внешний вызов ограничен явным разрешением; ошибка provider деградирует в безопасный диалог.

Отрицательные: чистое распознавание напева зависит от внешнего API, его каталога, тарифов и доступности; аудио покидает домашнюю сеть при включённом инструменте.
