# Одноразовое понимание детских фотографий

## Статус

Accepted

## Контекст

До этого Gateway мог только прикреплять к ответу лицензированное изображение
из Openverse. Клиенты не могли отправить фотографию. Для космического агента
нужно разбирать снимки ночного неба, не связывая мультимодальную модель с
текстовым LLM и не превращая фотографии ребёнка в постоянную историю.

Распознавание созвездий по одному телефонному снимку ненадёжно без даты,
примерного места и направления съёмки. Содержимое изображения также нельзя
считать доверенной инструкцией.

## Решение

Добавить четвёртый узкий application port `ImageUnderstandingProvider` и
OpenAI-compatible adapter. Он настраивается независимо от Chat, STT и TTS.
Capability выдаётся агенту инструментом `image_understanding`; первоначально
его получает только `space_guide`.

`POST /v1/vision/{conversation_id}/turn` принимает один JPEG, PNG или WebP и
вопрос. Gateway ограничивает тип и размер файла, передаёт байты Vision-провайдеру
и добавляет в текстовый ход только краткие наблюдения. Исходные байты:

- не записываются в PostgreSQL;
- не добавляются в `message_media`;
- не попадают в логи;
- освобождаются после завершения HTTP-запроса.

Наблюдения Vision считаются недоверенным контекстом. Инструкции на изображении
игнорируются. Провайдер не определяет личности и чувствительные признаки.
Космический агент обязан явно сообщать о неопределённости и запрашивать у
родителя дату, примерное место и направление наблюдения, когда это нужно.

Браузер и Android используют системный выбор уже созданной фотографии. Android
не запрашивает постоянный доступ к галерее и не сохраняет копию в приложении.

## Альтернативы

- Передавать изображение прямо в `ChatProvider`: отклонено, потому что выбор
  текстовой модели начал бы зависеть от поддержки Vision.
- Сохранять файл рядом с сообщением: отклонено ради минимизации детских данных и
  отсутствия продуктовой необходимости повторно обрабатывать фото.
- Определять созвездия только по пикселям: отклонено из-за высокой вероятности
  уверенной ошибки без времени, места и направления.
- Создать отдельный сетевой Vision Service сразу: отложено. Узкий provider port
  уже позволяет вынести adapter без изменения API и бизнес-логики.

## Последствия

Положительные:

- Vision-провайдер заменяется независимо;
- фотография не становится частью долговременных данных;
- способность выдаётся только выбранным агентам;
- одинаковый API работает в браузере и Android.

Отрицательные:

- для функции нужен отдельный мультимодальный model ID;
- повторный анализ старой фотографии невозможен без повторного выбора файла;
- качество астрономического ответа зависит от снимка и метаданных наблюдения.
