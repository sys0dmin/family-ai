# Воспроизводимые релизы через PowerShell и POSIX shell

## Статус

Принято

## Контекст

Gateway, Admin и Speech ранее обновлялись копированием отдельных файлов в
рабочие каталоги. Каталог кода одновременно содержал виртуальное окружение и
изменяемую конфигурацию. Нельзя было однозначно ответить, какой Git commit
запущен, повторить установку зависимостей или безопасно вернуть предыдущий код.

Проект использует два LXC-хоста и три systemd-службы. Управляющая рабочая станция
работает под Windows. Требуются точные пакеты, явные миграции, health-check и
откат без помещения секретов в Git или архив.

## Решение

Использовать малый release-controller:

- PowerShell выполняет сборку и SSH-оркестрацию с Windows;
- POSIX shell управляет релизами и systemd на Linux-хосте;
- Python из стандартной библиотеки собирает детерминированный `tar.gz` только из
  указанного Git commit;
- Gateway и Admin образуют один компонент `gateway`, поскольку используют один
  пакет, одно окружение зависимостей и одну схему БД;
- Speech образует независимый компонент `speech`;
- исходники хранятся в `/srv/family-ai/<component>/releases/<commit>`;
- `current` и `previous` являются атомарно переключаемыми символическими
  ссылками;
- окружения зависимостей хранятся по SHA-256 `uv.lock` и переиспользуются;
- конфигурация и секреты находятся только в `/etc/family-ai`;
- миграции подготавливаемого Gateway-релиза запускаются отдельной командой;
- после переключения выполняется health-check всех служб компонента; при ошибке
  `current` автоматически возвращается на прежний код.

Версия `uv` фиксируется в release-controller. Архив содержит манифест с commit и
хэшем lock-файла, а полный хэш архива проверяется до распаковки.

## Альтернативы

### Ansible

Даёт богатую модель inventory и ролей, но для двух однородных хостов добавляет
отдельную зависимость, bootstrap и больше DSL-кода. Формат релизов и каталогов
не привязан к shell, поэтому Ansible можно добавить при росте числа узлов.

### Docker/OCI

Упростил бы упаковку процесса, но потребовал бы новый runtime и отдельное решение
для больших speech-моделей. Текущие LXC и systemd уже обеспечивают нужную
изоляцию.

### Обновление Git checkout на сервере

Требует Git и доступ к репозиторию на production, смешивает сборку с запуском и
повышает риск попадания незакоммиченных файлов.

## Последствия

Положительные:

- один и тот же commit создаёт байт-в-байт одинаковый архив;
- production не нуждается в Git и не получает секреты внутри пакета;
- код и зависимости версии переключаются вместе;
- неудачный код автоматически откатывается после health-check;
- статус однозначно показывает запущенный commit.

Отрицательные:

- первая подготовка lock-файла требует доступа хоста к Python package indexes;
- speech-окружение занимает заметное место, хотя одинаковые lock-файлы
  дедуплицируются;
- автоматический откат касается только кода: обратимые миграции БД по-прежнему
  требуют отдельного осознанного решения;
- bootstrap systemd-контракта требует `sudo`.
