# Синтетический нагрузочный прогон голоса

`gateway.voice_soak` измеряет реальную производительность LLM, TTS и STT без
создания детского диалога. Команда использует только защищённые stateless
endpoints тест-студии и параллельно читает существующие локальные метрики.

## Что выполняется

Для каждого уровня параллельности `1`, `2` и `4` запускается заданное число
синтетических циклов:

1. короткий служебный запрос к LLM;
2. TTS одной заранее зафиксированной тестовой фразы;
3. STT полученного аудио;
4. сравнение распознавания с исходной синтетической фразой;
5. опрос очереди Speech и ресурсов Gateway, Database и Speech.

По умолчанию выполняются два цикла на worker: всего 14 измеряемых операций плюс
один warm-up. Это ограниченный эксплуатационный benchmark, а не бесконечный
stress-test. Допустимы только уровни `1`, `2` и `4`, а число циклов ограничено
десятью.

## Запуск

С рабочего Windows-компьютера одной командой:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File `
  .\scripts\operations\Invoke-VoiceSoak.ps1
```

Скрипт запускает benchmark на Gateway по SSH, сохраняет JSON в локальный
`.artifacts/voice-soak/` и удаляет временный отчёт с сервера.

На Gateway-хосте команда получает настройки и Admin credentials из существующего
`/etc/family-ai/gateway.env`. Файл передаётся напрямую `pydantic-settings` и не
исполняется как shell-скрипт:

```bash
cd /srv/family-ai/gateway/current
./.venv/bin/python -m gateway.voice_soak \
  --env-file /etc/family-ai/gateway.env \
  --levels 1,2,4 \
  --rounds 2 \
  --output /tmp/family-ai-voice-soak.json
```

Короткая проверка после изменения benchmark-кода:

```bash
./.venv/bin/python -m gateway.voice_soak --levels 1 --rounds 1
```

Не запускать одновременно с обычным использованием голосового интерфейса:
тест намеренно занимает очередь и CPU Speech Service. Для сравнимости сохранять
модель, beam/VAD, голос и число rounds неизменными.

## Отчёт

JSON имеет контракт `family-ai-voice-soak/v1` и содержит:

- successes, errors и error rate для каждого уровня;
- p50, p95, average и max для LLM, TTS, STT и полного цикла;
- similarity распознавания и технические confidence/duration;
- максимальную и среднюю очередь Speech;
- CPU, память и диск трёх серверов во время прогона;
- разницу общего числа сообщений до и после benchmark.

Файлы локальных прогонов следует складывать в `.artifacts/voice-soak/`, который
уже исключён из Git.

## Приватность и критерии провала

В отчёт не записываются:

- WAV/MP3;
- распознанный текст;
- ответ LLM;
- prompt целиком;
- conversation, message или turn identifiers;
- имена и данные ребёнка.

Сохраняется только стабильный `phrase_id`. Аудио существует в памяти worker до
завершения STT-запроса. Benchmark возвращает ненулевой exit code, если есть
ошибка этапа, similarity ниже порога, не удалось получить метрики или число
сообщений за последние 30 дней изменилось. Последняя проверка защищает от
случайного нарушения stateless-контракта, поэтому тест желательно запускать,
когда детский интерфейс не используется.

## Интерпретация

- рост p95 без роста p50 указывает на очередь или единичные тяжёлые запросы;
- последовательный рост обоих значений при `2` и `4` показывает насыщение CPU;
- `queue_max >= 2` подтверждает полезность текущего warning-порога;
- ошибки при `4`, которых нет при `1`, требуют ограничения параллельности, а не
  немедленной замены модели;
- высокое CPU само по себе не является ошибкой, если очередь освобождается и
  запросы завершаются без роста памяти.

Исходный отчёт не коммитится. В roadmap заносится только обезличенная сводка с
p50/p95, ошибками и максимальной очередью.

## Baseline J3710 от 15 августа 2026 года

Production-контур проверен с `--levels 1,2,4 --rounds 2`: 14 из 14 измеряемых
циклов завершились успешно, ошибок не было, `history_message_delta=0`.

| Параллельность | Total p50 | Total p95 | LLM p95 | TTS p95 | STT p95 | Queue max |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 13,5 с | 14,5 с | 1,7 с | 1,7 с | 11,2 с | 0 |
| 2 | 23,1 с | 25,0 с | 1,7 с | 12,2 с | 20,6 с | 1 |
| 4 | 44,2 с | 49,0 с | 2,8 с | 29,7 с | 41,0 с | 3 |

Ресурсы за 156 технических наблюдений:

- Speech CPU: p95 `94,4%`, max `94,7%`; память max `15,4%`;
- Gateway CPU: p95 `41,4%`, max `52,1%`; память max `21,7%`;
- Database CPU: p95 `12,0%`, max `22,2%`; память max `17,0%`.

Вывод: одиночный голосовой цикл укладывается в текущий эксплуатационный профиль,
два клиента уже конкурируют за Speech, а четыре почти линейно увеличивают
ожидание. Память стабильна, все запросы завершаются, поэтому менять модель или
железо только по этому тесту не требуется. Текущий warning `queue >= 2`
подтверждён: он срабатывает до зоны p95 около 49 секунд. Для обычного домашнего
режима разумный предел — не более двух одновременных voice-turn.
