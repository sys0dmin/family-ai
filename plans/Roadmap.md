# Family AI Mentor

## Roadmap

Версия: 0.4

Актуальные улучшения после Android-клиента и локального Speech Service
зафиксированы в [`ImprovementPlan.md`](ImprovementPlan.md).

## Цель MVP

Лера, 6 лет, открывает в браузере Android-планшета домашнюю страницу, удерживает большую кнопку микрофона, задаёт вопрос по-русски и получает короткий безопасный голосовой ответ.

MVP не требует чтения, аккаунта ребёнка, Matrix, Redis, локальной LLM или резервного копирования.

## Принципы реализации

- Сначала создаём один безопасный вертикальный сценарий, затем расширяем интерфейсы.
- Gateway содержит бизнес-логику; веб-клиент и будущий Matrix adapter остаются транспортом.
- OpenAI доступен только через Provider interface.
- Конфигурация агента отделена от Python-кода.
- Все API валидируют запросы и ответы и описаны в OpenAPI.
- Аудио не сохраняется; транскрипты хранятся 10 дней.
- Ceph — рабочее реплицируемое хранилище. Резервные копии в MVP не создаются.

## Этап 0. Архитектурная основа [ВЫПОЛНЕНО]

### Задачи

- Зафиксировать ADR и данную архитектуру.
- Создать структуру Gateway, тестов, конфигурации и документации.
- Определить `.env.example` без секретов.
- Настроить форматирование, линтер, тесты и проверку OpenAPI.

### Готово, когда

- проект запускает пустой FastAPI-сервис;
- `GET /healthz` возвращает успешный ответ;
- локальные проверки выполняются одной командой;
- секреты не попадают в репозиторий и логи.

## Этап 1. Данные и безопасный текстовый контур [ВЫПОЛНЕНО]

### Задачи

- Поднять PostgreSQL на диске Ceph.
- Создать SQLAlchemy-модели и миграции: child profile, conversation, message, topic statistic.
- Создать профиль Леры: русский язык, возраст 6 лет.
- Реализовать единый conversation API и сохранение текста сообщений.
- Реализовать ежедневное удаление сообщений старше 10 дней.
- Добавить тесты политики хранения.

### Готово, когда

- текстовый запрос проходит валидацию и создаёт сообщение в нужном диалоге;
- сообщение старше 10 дней удаляется автоматически;
- агрегированная статистика не содержит текст сообщения;
- миграции воспроизводимо применяются на чистой базе.

## Этап 2. Provider и агент «Учитель-друг» [ВЫПОЛНЕНО]

### Задачи

- Определить внутренние модели Provider request/response и интерфейсы STT, LLM, TTS.
- Реализовать OpenAI provider через этот интерфейс.
- Добавить конфигурацию единственного агента: системные правила, короткие ответы, русский язык, возраст 6 лет.
- Добавить unit-тесты Gateway с подменным provider.
- Реализовать технические ошибки без утечки внутренних деталей.

### Готово, когда

- Gateway не импортирует OpenAI SDK вне провайдерного модуля;
- тестовый provider позволяет проверять бизнес-логику без сетевого вызова;
- текстовый диалог возвращает ответ агента и сохраняет его.

## Этап 2.5. Версионные агенты и выбор персонажа [ВЫПОЛНЕНО]

### Задачи

- Хранить карточки агентов и неизменяемые версии промптов в PostgreSQL.
- Закреплять точную ревизию агента за каждым новым диалогом.
- Оставить обязательную основу детской безопасности вне редактируемого промпта.
- Добавить в админку редактор карточек, голосов, версий и явную публикацию.
- Добавить в детский интерфейс крупные карточки выбора агента.

### Готово, когда

- ребёнок видит только включённых агентов без системных промптов;
- смена агента начинает новый диалог;
- публикация новой версии не меняет уже начатые диалоги;
- голос TTS выбирается из конфигурации закреплённого агента.

## Этап 3. Safety pipeline [ВЫПОЛНЕНО]

### Задачи

- Добавить формальные проверки входа, выхода, инструментов и permissions.
- Описать политики для персональных данных, опасных инструкций и не подходящих возрасту тем.
- Добавить безопасные шаблоны отказа и рекомендацию обратиться к взрослому при необходимости.
- Добавить набор тестовых сценариев безопасности.
- Добавить в защищённую админку каталог правил, обезличенные счётчики и запуск
  контрольной матрицы без возможности отключить обязательные правила.

### Готово, когда

- неподходящий запрос не передаётся провайдеру либо получает безопасный маршрут;
- неподходящий ответ не возвращается ребёнку;
- критические сценарии безопасности покрыты автоматическими тестами;
- логи не содержат содержание сообщений или секреты.

## Этап 4. Голосовой вертикальный сценарий [ВЫПОЛНЕНО]

### Задачи

- Реализовать `POST /v1/voice/turn`.
- Преобразовывать аудио в текст через provider, обрабатывать диалог и синтезировать ответ.
- Не сохранять исходные аудиофайлы.
- Ограничить длительность и размер аудиозаписи.
- Проверить задержку и качество на русской речи.

### Готово, когда

- аудиозапись проходит полный путь STT → Gateway → LLM → TTS;
- ответ возвращается как аудио;
- после завершения обработки аудио недоступно на сервере;
- ошибки распознавания и провайдера понятны и безопасны для ребёнка.

## Этап 5. Детский Android-клиент [ВЫПОЛНЕНО]

### Задачи

- Сделать минимальный адаптивный интерфейс: кнопка микрофона, статусы, остановка ответа.
- Раздать PWA через локальный HTTPS.
- Настроить доверие локальному сертификату на планшете.
- Ограничить доступ Gateway домашней сетью firewall-правилами.

### Готово, когда

- PWA устанавливается как ярлык на Android-планшет;
- браузер получает разрешение на микрофон по HTTPS;
- Лера может выполнить голосовой диалог без чтения и логина;
- с внешней сети сервис недоступен.

## Этап 6. Родительская статистика [ВЫПОЛНЕНО]

### Задачи

- Показать число диалогов, длительность, активные темы и новые интересы.
- Не показывать транскрипты или содержание сообщений.
- Закрыть административный путь отдельной защитой.

### Готово, когда

- родитель видит только агрегированные сведения;
- детская страница не может получить статистику;
- статистика продолжает работать после удаления истории сообщений.

## После MVP

1. Текстовый чат поверх существующего API.
2. Streaming STT/TTS и более быстрый голосовой ответ.
3. Новые конфигурационные агенты и специализированные инструменты для них.
4. Matrix adapter как дополнительный транспорт.
5. Redis — только при появлении задачи очередей, rate limiting или кэширования.
6. Локальные STT/TTS/LLM через Provider interface.
7. Vision, безопасные домашние эксперименты и дополнительные родительские правила.

## Этап 9. Космический агент и одноразовый Vision [ВЫПОЛНЕНО]

- Добавлен версионируемый агент «Алиса Селезнёва» для реальной астрономии и
  явно запрошенных фантастических путешествий.
- Добавлен независимый `ImageUnderstandingProvider`.
- Браузер и Android могут отправить Алисе JPEG, PNG или WebP.
- Файл не сохраняется; в историю попадают только вопрос и ответ.
- Для снимков неба действуют правила неопределённости и безопасного наблюдения.
- Настройки провайдера, модели, endpoint и ключа доступны в админке.

Архитектура и эксплуатация описаны в
[`ADR 027`](../docs/adr/027-ephemeral-image-understanding.md) и
[`docs/image-understanding.md`](../docs/image-understanding.md).

## Этап 11. Мультимодальный режим «Покажи и спроси» [ВЫПОЛНЕНО]

- Добавлен provider-neutral `POST /v1/multimodal/{conversation_id}/turn`.
- STT и Vision выполняются параллельно, а в диалог попадает только текст.
- Учитель-друг, Мурка, Байтик и Алиса получают управляемую из админки
  возможность понимать фотографии.
- Android предлагает крупный выбор камеры или галереи и принимает вопрос
  голосом без текстового ввода.
- Временное превью очищается, поздний отменённый ответ не воспроизводится,
  готовый безопасный ответ доступен через обычный voice replay.
- Метрики разделяют STT, Vision, LLM, TTS и полное серверное время.
- Детские фото и аудиозаписи не сохраняются и не входят в тестовый набор.

Архитектура и эксплуатация описаны в
[`ADR 029`](../docs/adr/029-ephemeral-spoken-image-turns.md) и
[`docs/multimodal-spoken-image.md`](../docs/multimodal-spoken-image.md).

## Этап 12. Voice 2.0 [ВЫПОЛНЕНО]

- Gateway отдаёт проверенный ответ короткими NDJSON-аудиочастями.
- Android начинает воспроизведение после первой части и готовит единый WAV для
  повторного прослушивания.
- Старые one-shot endpoints сохранены как автоматический fallback.
- Отмена останавливает плеер и предотвращает синтез следующих частей.
- Админка разделяет полное время и воспринимаемую задержку до первого звука.

Полевой замер двух мультимодальных ходов на J3710 показал первый звук через
15,3–15,94 с против one-shot baseline 29,5 с: воспринимаемая задержка сократилась
примерно на 46–48%, очередь Speech оставалась свободной, ошибок не было.
Архитектура и runbook:
[`ADR 030`](../docs/adr/030-ndjson-voice-streaming.md) и
[`docs/voice-streaming.md`](../docs/voice-streaming.md).

## Этап 13. Родительская обратная связь [ВЫПОЛНЕНО]

- В истории ответ агента можно отметить стабильной причиной и родительской
  заметкой; текст сообщения в feedback не копируется.
- Аналитика показывает распределение проблем за выбранный период.
- Feedback удаляется вместе с сообщением по 10-дневному retention.
- Постоянный regression case создаётся только после просмотра, редактирования и
  явного подтверждения полного текста родителем.
- Подтверждённые кейсы запускаются в тест-студии через production-like pipeline
  со сравнением ответа, safety status, rule id и технической ошибки.
- Экспорт содержит только подтверждённый набор, а кейсы удаляются отдельно и
  явно.

Архитектура и эксплуатация:
[`ADR 031`](../docs/adr/031-parent-feedback-regression-lifecycle.md) и
[`docs/parent-quality.md`](../docs/parent-quality.md).

## Этап 14. Голосовые приключения и занятия [ВЫПОЛНЕНО]

- Сценарии являются валидируемой конфигурацией, а не отдельными Python-классами.
- Исходные пять четырёхшаговых занятий сохранены без изменения версий.
- Добавлено восемь оригинальных шестишаговых приключений — по одному для
  каждого агента; предыдущий голосовой выбор влияет на следующую сцену.
- Пауза сохраняет текущий шаг, а продолжение не повторяет вступление.
- Финал ограничен, не создаёт streak, награды за удержание или бесконечную
  историю; долгосрочный результат подтверждает только родитель.

Архитектура и эксплуатация:
[`ADR 032`](../docs/adr/032-configured-activity-sessions.md) и
[`docs/activities.md`](../docs/activities.md).
