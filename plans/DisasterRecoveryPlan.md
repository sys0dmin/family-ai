# Family AI Disaster Recovery Plan

- Версия: 1.0
- Дата: 28 июля 2026 года
- Статус реализации: скрипты и runbook готовы; обязательный clean-room fire drill
  ещё не выполнен.

Проверено на production-источнике 28 июля 2026 года без остановки и изменения
основной БД: consistent custom `pg_dump`, двукратный manifest,
`pg_restore --list`, скачивание по SCP и совпадение SHA-256. Выполнен полный
логический restore в отдельную временную БД на том же PostgreSQL-хосте; manifests
совпали, после проверки тестовая БД и dump удалены. Восстановление в новые VM
намеренно остаётся отдельным fire drill и не считается проверенным до появления
трёх изолированных targets.

## Цели

- восстановить Gateway, PostgreSQL и Speech на трёх новых Debian 13 VM;
- не требовать старых дисков Gateway/Speech;
- не выполнять разрушительных операций над найденной старой БД;
- при доступной PostgreSQL перенести всю логическую БД с проверкой строк;
- не помещать секреты, dump или детские сообщения в Git;
- получить одинаковый Git commit в `origin/main` и production.

## Сценарий A. Полная потеря

Результат:

- создаётся пустая PostgreSQL;
- Alembic восстанавливает актуальную схему и стартовые конфигурации агентов;
- runtime-секреты восстанавливаются из DR-kit;
- история сообщений, родительская память и изменения агентов, существовавшие
  только в погибшей БД, потеряны.

RPO: вся БД.

## Сценарий B. Database salvage

Результат:

- старая БД остаётся неизменной;
- consistent `pg_dump` переносится в пустую новую PostgreSQL;
- до миграций сверяются версия схемы и точные количества строк всех таблиц;
- затем новая БД обновляется до текущей Alembic head.

RPO: изменения после snapshot. При остановленных writer-процессах — 0.

## Критерии готовности

- [x] DR-kit шифруется Windows DPAPI и исключён из Git;
- [x] clean-host bootstrap создаёт системных пользователей и зависимости;
- [x] target guard запрещает восстановление поверх существующей системы;
- [x] реализован `TotalLoss`;
- [x] реализован `DatabaseSalvage`;
- [x] dump проверяется SHA-256 и восстанавливается одной транзакцией;
- [x] сравниваются source/target manifest;
- [x] код разворачивается из точного Git commit;
- [x] выполняются health-check и сетевое ограничение сервисных портов;
- [x] временные файлы очищаются;
- [x] написан подробный runbook;
- [ ] выполнить первый fire drill на трёх изолированных тестовых VM;
- [ ] записать фактический RTO и найденные отклонения;
- [ ] повторять fire drill после изменения PostgreSQL/Speech bootstrap и не реже
  одного раза в год.
