# Family AI Mentor

## План дальнейших улучшений

- Версия: 1.1
- Дата фиксации: 24 июля 2026 года

## Цель

Развивать Family AI как надёжного домашнего голосового наставника для Леры,
сохраняя понятную архитектуру, детскую безопасность, приватность и возможность
независимо заменять инфраструктурные компоненты.

Этот документ дополняет основной `Roadmap.md`. Он фиксирует следующие улучшения
после появления Android-клиента, локальных STT/TTS, нескольких агентов,
родительской админки и инфраструктурного мониторинга.

## Что уже хорошо и не требует переделки

- PostgreSQL остаётся основной базой данных.
- Gateway остаётся единственным местом для бизнес-логики.
- Агенты остаются версионируемой конфигурацией, а не Python-кодом.
- Speech Service остаётся отдельным OpenAI-совместимым сервисом.
- Исходное аудио не сохраняется.
- Облачный speech fallback не включается автоматически.
- Текущие пять голосов Silero сохраняются без подключения лишних TTS-движков.
- Мониторинг ограничивается тремя серверами проекта и не захватывает Proxmox,
  Ceph и остальные домашние ресурсы.

## Порядок реализации

### Этап 0. Завершить разделение safety-входа и safety-выхода

Статус: выполнено и сохранено в Git.

Причина: одинаковая проверка вопроса ребёнка и ответа модели создавала ложные
блокировки. Например, безопасный факт про кровь осьминога заменялся аварийным
fallback.

Задачи:

- проверять входящий вопрос консервативным набором правил;
- проверять ответ модели только на конкретные опасные инструкции и раскрытие
  чувствительных значений;
- разрешать познавательные и предупреждающие упоминания потенциально опасных
  тем;
- журналировать идентификатор сработавшего правила без текста ответа;
- покрыть ложные и настоящие срабатывания автоматическими тестами.

Готово, когда один и тот же безопасный вопрос стабильно получает содержательный
ответ, а явная инструкция взять спички и развести огонь по-прежнему блокируется.

### Этап 1. Наблюдаемость голосового конвейера

Статус: выполнено 23 июля 2026 года.

Задачи:

- [x] измерять отдельно длительность записи, STT, LLM, TTS и полного voice turn;
- [x] показывать текущую очередь Speech Service и активный тип inference;
- [x] считать успешные запросы, ошибки и этап сбоя;
- [x] добавить эти данные во вкладку «Инфраструктура» без хранения аудио и текста;
- [x] показывать уверенность последнего STT для настройки порогов.

Готово, когда из админки видно, где именно Лера ждёт и почему CPU Speech Service
находится под полной нагрузкой.

Архитектурное решение: расширить ADR мониторинга приложения-level метриками, не
добавляя Prometheus или отдельную time-series базу до появления реальной
необходимости.

### Этап 2. Тестовая студия агентов и голосов

Статус: выполнено 23 июля 2026 года.

Задачи:

- [x] добавить в админку отдельный безопасный тестовый режим;
- [x] позволить выбрать агента, ввести контрольную фразу и прослушать его голос;
- [x] показывать сырой ответ модели, результат после safety и идентификатор
  сработавшего правила;
- [x] не добавлять тестовые сообщения в детскую историю;
- [x] добавить короткие предустановленные проверки для всех пяти голосов Silero.

Готово, когда родитель может проверить новую ревизию prompt, safety и голос до
публикации и без создания тестового диалога Леры.

### Этап 3. Настройка STT под детскую речь

Статус: выполнен 24 июля 2026 года, включая первый полевой замер на J3710.

Задачи:

- [x] добавить локальный initial prompt со словами «Лера», «Мурка», «Байтик» и
  именами остальных агентов;
- [x] возвращать техническую оценку уверенности и признак отсутствия речи;
- [x] различать тишину, слишком короткую запись и низкую уверенность;
- [x] реализовать автоматическое сравнение VAD вкл./выкл. и beam size 1/3/5
  непосредственно на J3710 с точностью, отбрасыванием тишины и задержкой;
- [x] подготовить серверный набор из 12 известных фраз и 3 проверок тишины без
  помещения записей Леры в Git, историю сообщений или облако;
- [x] пройти первую полевую калибровку и применить рекомендованные VAD/beam из
  фактического отчёта.
- [x] добавить в защищённую админку изменение beam/VAD, постоянный runtime-конфиг
  и проверяемый перезапуск только `family-ai-speech.service`.

Результат первого замера: `VAD=true`, `beam_size=5`, точность 53%,
отбрасывание тишины 100%, среднее время 7,95 секунды, P95 10,4 секунды.
Перестановка ребёнком слов считается текущей WER-метрикой ошибкой, поэтому
процент отражает строгое совпадение фразы и не является оценкой понятности речи.

Готово, когда имена агентов и типичные детские фразы распознаются устойчивее, а
неудачная запись получает понятный повтор без случайной транскрипции.

### Этап 5. Разделение provider-интерфейсов

Приоритет: архитектурный, выполнить до подключения нового LLM или speech engine.

Задачи:

- выделить `ChatProvider`;
- выделить `SpeechRecognitionProvider`;
- выделить `SpeechSynthesisProvider`;
- оставить совместимый OpenAI adapter для каждого контракта;
- внедрять провайдеры в сервисы независимо;
- сохранить текущие публичные REST API без изменений.

Готово, когда OpenAI-compatible LLM, локальный STT и локальный TTS можно
переключать независимо без создания искусственного общего provider-объекта.

Для изменения потребуется отдельный ADR и инкрементальная миграция без
переписывания работающего Gateway.

### Этап 7. Воспроизводимое развёртывание

Статус: выполнено 25 июля 2026 года и проверено на production.

Задачи:

- [x] создать одну идемпотентную команду развёртывания каждого сервиса;
- [x] собирать пакет только из конкретного Git commit;
- [x] применять миграции отдельно и явно;
- [x] выполнять health-check после перезапуска;
- [x] хранить номер развёрнутой версии и позволять откатить код сервиса;
- [x] не помещать секреты в пакет, stdout или Git.

Готово, когда Gateway, Admin и Speech обновляются одинаковым предсказуемым
процессом без ручного копирования отдельных файлов.

Gateway/Admin и Speech переведены на каталоги релизов в `/srv/family-ai`,
точные окружения по хэшу `uv.lock` и внешнюю конфигурацию в `/etc/family-ai`.
Проверены: детерминированная сборка, отдельный запуск Alembic, автоматический
health-check, автоматический возврат после неуспеха, ручной rollback на legacy и
повторное развёртывание Speech.

Архитектурное решение:
[`ADR 023`](../docs/adr/023-reproducible-shell-releases.md).
Эксплуатационная инструкция:
[`docs/deployment.md`](../docs/deployment.md).

### Этап 8. Родительская долгосрочная память

Статус: выполнено и развёрнуто в production 28 июля 2026 года.

Задачи:

- [x] хранить интересы, предпочтения и учебный прогресс отдельно от 10-дневной
  истории сообщений;
- [x] добавлять только структурированные факты с источником и датой;
- [x] позволить родителю просматривать, исправлять и удалять каждую запись;
- [x] запретить модели самостоятельно превращать предположение в долгосрочный факт;
- [x] не использовать память для давления, удержания внимания или замены родителей.

Готово, когда агент помнит подтверждённые интересы Леры после очистки истории, а
родитель полностью контролирует содержимое памяти.

Реализован изолированный provider-neutral домен `gateway.app.memory` с
repository-портом. Детский и provider API не имеют операции записи; CRUD
доступен только через защищённую вкладку «Память». Изменение повторно
подтверждает факт, удаление физическое, а родительская заметка об источнике не
передаётся модели.

Архитектурное решение:
[`ADR 024`](../docs/adr/024-parent-managed-long-term-memory.md).
Политика и API:
[`docs/long-term-memory.md`](../docs/long-term-memory.md).

## Выполненный срез 23 июля 2026 года

Итерация объединила этапы 1, 2 и основной контур этапа 3:

1. измерение STT, LLM, TTS и общего voice turn;
2. очередь и состояние Speech Service;
3. отображение метрик в админке;
4. тестовая фраза и предпрослушивание пяти голосов;
5. тест агента без записи в детскую историю.

Следующий шаг — пройти один управляемый родителем локальный сеанс по
[`docs/stt-calibration-guide.md`](../docs/stt-calibration-guide.md), получить
фактический отчёт J3710 и только после этого менять production VAD/beam или
модель.

## Не включено в ближайший план

- wake word и постоянное прослушивание микрофона;
- автоматическая отправка детского аудио в облачный fallback;
- новые TTS-движки только ради увеличения числа голосов;
- локальная LLM на текущем J3710;
- мониторинг Proxmox, Ceph и посторонних контейнеров;
- резервное копирование в рамках текущего домашнего MVP;
- публичный доступ из интернета.
