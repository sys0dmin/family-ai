# Family AI для Android

Нативный Flutter-клиент детского интерфейса. Gateway остаётся источником
агентов, истории и AI-логики; приложение не содержит промптов, секретов или
захардкоженного адреса домашней сети.

## Границы модулей

- `GatewayClient` содержит сценарии API, а HTTP-заголовки, единые ошибки и JSON
  transport вынесены в `gateway_client_transport.dart`;
- `ChatScreen` координирует контроллеры, а визуальные компоненты приключений и
  фото находятся в `chat_screen_widgets.dart`;
- `VoiceChatController` управляет жизненным циклом записи и отменой, а Voice 2.0
  streaming/legacy execution — в `voice_turn_runner.dart`;
- изображения из `mobile/assets/characters` являются проверяемым зеркалом
  канонического `gateway/static/assets/characters`, а не второй точкой правки.

Это Dart `part` одной библиотеки: приватность реализации сохраняется, публичные
контракты экранов, `ConversationGateway` и тестовых doubles не меняются.

## Возможности

- ручной ввод адреса Gateway с автоматическим добавлением `http://`;
- проверка сервера через `GET /healthz` до сохранения;
- локальное хранение только нормализованного адреса;
- смена адреса из экрана выбора персонажей;
- визуальные карточки всех доступных агентов;
- восстановление последнего разговора отдельно для каждого агента;
- текстовый диалог и отображение фотографий из ответов;
- голосовой диалог с автоматическим воспроизведением ответа;
- голосовой режим «Покажи и спроси» через камеру или галерею;
- повторное прослушивание ответов агента из управляемого локального кеша;
- двухшаговое визуальное подтверждение нового разговора;
- управляемую родителем калибровку STT без ручной работы с аудиофайлами.

## Голосовой диалог

Кнопка микрофона записывает WAV 16 кГц/моно и отправляет его в
`POST /v1/voice/{conversation_id}/turn`. Одна реплика ограничена 55 секундами.
Временный файл удаляется сразу после чтения; исходное аудио локально и на
Gateway не сохраняется. В истории остаются распознанный текст ребёнка и ответ
агента. Полученный TTS-ответ воспроизводится автоматически.

Работа с микрофоном и проигрывателем изолирована интерфейсом `VoiceSession`,
поэтому реализацию можно заменить независимо от экрана диалога и API-клиента.
Android запрашивает разрешение `RECORD_AUDIO` при первой записи.

Готовые ответы агента кешируются в приватном каталоге приложения по
идентификаторам разговора и сообщения. Кнопка динамика повторяет кешированный
ответ; если файла нет, приложение вызывает
`POST /v1/voice/{conversation_id}/synthesize` и сохраняет результат. Кеш
ограничен 10 днями и 100 МБ. При создании нового разговора кеш предыдущего
разговора удаляется. Записи ребёнка в кеш не попадают.

Перед сохранением и воспроизведением клиент нормализует размеры RIFF и `data`
в потоковых WAV-ответах. Это обеспечивает совместимость с Android MediaPlayer,
который не принимает незавершённые размеры `0xFFFFFFFF`.

## Покажи и спроси

У агентов с capability `supports_spoken_image_question` кнопка фотографии
открывает крупный визуальный выбор камеры или галереи. После выбора приложение
сразу включает запись: Лере не требуется печатать вопрос. Один multipart-запрос
в `POST /v1/multimodal/{conversation_id}/turn` отправляет временные байты фото и
WAV-запись.

Локальное превью показывается только во время текущего хода и очищается после
ответа, ошибки или отмены. Поздний ответ отменённой операции не воспроизводится.
Текст, сохранённый Gateway, загружается по `X-Family-AI-Message-Id`, а готовое
аудио использует тот же 10-дневный replay-кеш, что обычный голосовой диалог.
Исходная запись ребёнка в кеш не попадает.

Подробный API, safety и проверка после релиза:
[`../docs/multimodal-spoken-image.md`](../docs/multimodal-spoken-image.md).

## Калибровка детской речи

Калибровку запускает только родитель из «Тест-студии» админки. Приложение
проверяет наличие активной сессии на экране выбора персонажей, открывает
визуальный сценарий и озвучивает задания через серверный TTS. Для обычной фразы
ребёнок нажимает большую кнопку до и после ответа. Три образца тишины
записываются автоматически.

Временный файл Android удаляется сразу после чтения. Серверные образцы
используются только локальным Speech Service и удаляются автоматически.
Подробная родительская памятка находится в
[`../docs/stt-calibration-guide.md`](../docs/stt-calibration-guide.md).

## VS Code

Установить рекомендованное расширение `Flutter` от Dart Code. Репозиторий уже
указывает VS Code на переносимый SDK в `.tools/flutter`. Проверить окружение:

```powershell
.\.tools\flutter\bin\flutter.bat doctor -v
```

Android Studio не требуется. Для сборки нужны Flutter SDK, JDK 17, Android SDK
Platform 36, Build Tools 36 и принятые Android licenses. На текущей машине они
установлены переносимо в `.tools/`, который не входит в Git.

После первого клонирования получить зависимости:

```powershell
cd mobile
..\.tools\flutter\bin\flutter.bat pub get
```

## Сборка APK

Debug-сборка для разработки:

```powershell
cd mobile
..\.tools\flutter\bin\flutter.bat build apk --debug
```

Результат: `mobile/build/app/outputs/flutter-apk/app-debug.apk`.

Подписанная release-сборка создаётся только штатным скриптом из точного Git
commit:

```powershell
.\scripts\mobile\Initialize-AndroidSigning.ps1
.\scripts\mobile\Build-AndroidRelease.ps1 -Commit HEAD
```

Keystore и пароли находятся вне Git. APK, SHA-256 и release manifest попадают в
игнорируемый каталог `.artifacts\android`. Полная инструкция по инициализации,
восстановлению ключа и обновлению приложения без потери адреса Gateway:
[`../docs/android-release.md`](../docs/android-release.md).

## Архитектура чата

- `ConversationGateway` отделяет экран от конкретного HTTP-клиента;
- `ConversationController` управляет историей, текстовыми ходами и диалогом;
- `VoiceChatController` управляет записью, replay, кэшем и voice turn;
- `chat_widgets.dart` содержит независимые визуальные компоненты;
- `chat_screen.dart` только связывает контроллеры и адаптивную раскладку.

Voice UX использует один автомат состояний: `idle`, `listening`,
`understanding`, `looking`, `thinking`, `speaking`, `error`. Кнопка отмены
инвалидирует активную операцию, очищает временную фотографию, останавливает
плеер и отменяет оставшиеся части на Gateway.

Voice 2.0 использует NDJSON-поток: первая полностью проверенная WAV-часть
проигрывается до готовности всего ответа. Совместимые части объединяются для
replay; при старом Gateway клиент автоматически использует one-shot endpoint.
Контракт и проверка описаны в
[`../docs/voice-streaming.md`](../docs/voice-streaming.md).

## Запуск на физическом Android-устройстве

1. Включить на телефоне режим разработчика и «Отладку по USB».
2. Подключить телефон и подтвердить доверие компьютеру.
3. Проверить подключение:

```powershell
.\.tools\android-sdk\platform-tools\adb.exe devices
```

4. Запустить из корня репозитория:

```powershell
cd mobile
..\.tools\flutter\bin\flutter.bat run
```

Телефон должен находиться в одной домашней сети с Gateway. HTTP разрешён для
текущего LAN-развёртывания; для доступа через недоверенную сеть потребуется
HTTPS.
